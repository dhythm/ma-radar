# ma-radar

M&A 案件（事業承継・サイト売買など）を集めて、条件でスコアリングして眺められる Web サービス。個人開発プロジェクト。

## コンセプト

- ラッコM&A（https://rakkoma.com/project/list）等の公開案件を定期収集し、一覧・検索・絞り込みができるサイトにする
- 案件ごとにスコアを付ける。重視する観点：
  - 特別なスキルが要らない（運用がシンプル）
  - 初期費用が少ない（在庫なし・固定費が低い）
  - 一人で回せる
  - 売却理由が「忙しくなったから」（事業自体は好調）
  - 事業価値がすでに見出されている（実績・利用者・収益が検証できる）
  - YouTube チャンネルの案件は除外
- 価格や利益の数字は売主の掲載値であることを明示する

## 技術方針

- データ収集は Node スクリプト（スクレイパー）で行い、結果を JSON としてリポジトリに保存する
- フロントは Vite + React + TypeScript の静的サイトで、その JSON を読み込む（サーバー代・API 課金なし）
- 定期収集は GitHub Actions（無料枠）で回す
- UI はライトモード基調

## 開発の進め方

- 実装は Codex CLI（gpt-6.2-astra / Ultrafast）に委任し、成果物をレビューして取り込む
- 小さな単位でコミットし、main は常に動く状態を保つ
- スクレイパーは対象サイトの負荷にならない頻度・実装にし、robots と利用規約を確認してから動かす

## まず作るもの（v1）

1. ラッコM&A 一覧の収集スクリプト（タイトル・価格・月利益・カテゴリ・URL・掲載日）
2. スコアリング（上記観点のキーワード・数値条件による機械判定＋理由の表示）
3. 一覧 UI：スコア順・価格帯・キーワードで絞り込み、案件詳細へのリンク
4. GitHub Actions による日次収集

## 使い方

Node.js 22 の最新版で `npm install` してから、以下を実行します。GitHub Actions の `npm ci` と npm キャッシュを使うには、このとき生成される `package-lock.json` を事前にリポジトリに含めてください。

- 収集: `npm run collect`（既定は一覧1ページ、保存先は `data/projects.json`）
- 通信なしで収集を試す: `npm run collect -- --file scripts/__fixtures__/list.html --out /tmp/ma-radar-projects.json`
- 開発: `npm run dev`
- テスト: `npm test`
- ビルド: `npm run build`

robots.txt に配慮し、専用の User-Agent を明示します。複数ページ収集時は Crawl-delay に従って10秒待ち、定期収集は1日1回（日本時間9時）です。
価格・利益は売主の掲載値であり、検証済みの数値ではありません。
